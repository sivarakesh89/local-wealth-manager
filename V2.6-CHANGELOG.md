# FinMate v2.6.0

## Fixes and improvements
- Fixed PIN setup failure caused by the data encryption key being non-extractable after a password unlock. PIN and biometric wrappers can now be created after unlocking an existing vault.
- Kept PIN entry masked and restricted to exactly 4 digits.
- Unlock screen continues to offer every enabled method: PIN, device biometrics, and master password.
- Removed forced `prompt=consent` from the normal Google Drive GIS token request so Google can reuse an existing grant instead of unnecessarily forcing the consent/testing screen on every attempt.
- Added exact Authorized redirect URI display/copy action and explicitly warns against tracking/query parameters in the fallback redirect URI.
- Google diagnostics now show the exact fallback redirect URI.
- Improved PDF import by reconstructing text into positioned lines and using PDF.js without a worker for this local import path, reducing worker serialization/password issues.
- PDF import now separates extraction errors from save/render errors so successfully detected transactions are not incorrectly reported as an unreadable PDF.
- PDF-imported Debit rows are Expenses and Credit rows are Income, with basic category inference for common descriptions.
- Added best-effort ticker inference during investment import from explicit symbols, common instrument names, common Indian/US names, and Gold/Silver/Crypto asset types. Explicit CSV ticker/symbol always wins.
- Fixed the Transactions page table so wide imported transaction data scrolls horizontally instead of collapsing the whole page.
- Improved custom background images with a subtle Gmail-like translucent/blurred treatment; the selected theme remains visible underneath and can be restored with “Use selected theme.”
- Updated PWA/service-worker cache to v2.6.
