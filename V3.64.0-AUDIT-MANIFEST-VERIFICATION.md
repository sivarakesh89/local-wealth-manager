# FinMate v3.64.0 — Audit Manifest Verification

## Purpose
Adds a read-only check that compares an exported `FinMate-Audit-Verification-Manifest.json` with the currently loaded conflict-apply audit report.

## How to test
1. Keep prior ZIPs and backups unchanged.
2. Deploy the ZIP contents to the existing GitHub Pages repository.
3. Confirm About → Version shows `3.64.0`.
4. Open a valid v3.60.0 conflict-apply audit JSON in Sync → View saved audit report.
5. Click **Export verification manifest** and save the manifest.
6. Click **Verify saved manifest**, select the manifest just exported, and confirm every check passes: report fingerprint, creation time, app version, report format, validation status, decision count, and summary counts.
7. Change a copy of the manifest fingerprint to another valid 64-character hexadecimal string; verification must report a mismatch.
8. Change a summary count in a copy of the manifest; verification must report a mismatch.
9. Select unrelated JSON or malformed manifest JSON; it must be rejected with an understandable message.
10. Cancel the file picker; FinMate should remain usable.
11. Confirm vault contents, pending-change count, Drive, shared baseline, and media remain unchanged.

## Safety and limitations
- Manifest verification is read-only and does not persist changes to the vault, pending journal, Drive, shared baseline, or media.
- The check compares manifest claims to the loaded report; it does not prove the report's authenticity or who created it.
- SHA-256 fingerprints and manifests are not digital signatures. If both files are modified together, this comparison alone cannot establish authenticity.
- No live GitHub Pages/browser or Google Drive test was performed as part of packaging.
