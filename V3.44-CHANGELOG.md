# FinMate v3.44.0 changelog

- Fixed the post-Google-OAuth unlock path so it does not immediately re-encrypt the entire vault just to save OAuth token metadata. The explicit Drive operation now persists once after folder resolution, before upload. Removed the redundant post-upload full-vault encryption.
- Added a pre-unlock **Download encrypted recovery copy** button. It exports the current IndexedDB vault record without decrypting it, useful if the large-vault unlock/render flow is unstable. The file remains encrypted and requires the master password.
- Reduced transient memory pressure by avoiding unnecessary deep clones when syncing/loading the active profile and by storing a canonical profile snapshot in the encrypted vault instead of duplicating the active profile's arrays at both the root and inside the profile. Existing vaults remain readable and are migrated on the next successful save.
- New image attachments larger than 180 KB are compressed where supported (maximum 1800 px, JPEG quality 0.84) before storage. PDFs and non-image documents are left unchanged. Existing images are not destructively recompressed in-place.
- Reordered rebalancing dropdowns to: **Ideas based on your entered targets**, **Sector-wise rebalancing ideas**, **Existing individual asset targets**. Sector-wise ideas are now a separate dropdown from the sector target planner.

## Recovery and data safety

- IndexedDB database name remains `LWMVault`; the encrypted vault record remains compatible with the existing master-password wrapper and AES-GCM encrypted payload.
- The pre-unlock emergency backup copies the encrypted record as-is; keep it private and retain the master password. Do not clear browser/site data or recreate the vault while recovering existing data.
- This release reduces duplicate serialization and new-image size. A complete separate encrypted attachment store with independently synced Drive sidecar files requires a further staged migration so legacy jewellery photos, invoices, and property documents can be moved and recovered safely; that migration is not claimed as completed in this release.
