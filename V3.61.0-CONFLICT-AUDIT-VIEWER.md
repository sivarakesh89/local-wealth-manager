# FinMate v3.61.0 — Conflict Apply Audit Viewer

## What changed
- Adds a read-only viewer on the Sync page for a previously exported `FinMate-Local-Conflict-Apply-Audit.json` report.
- Shows report date/version/scope, summary counts, decisions, local actions, before/after local SHA-256 fingerprints, and local record presence before/after.
- Validates the report format, required decision fields, allowed decisions, SHA-256 fingerprint shape, and summary counts before displaying it.
- Adds an optional human-readable HTML export of the currently opened report.
- Does not write audit reports into the vault, localStorage, Google Drive, shared baseline, or media store. To view an older report, select the JSON file you previously saved.

## Important limitations
- Structural checks do not prove that a report is authentic, signed, or independently truthful. Reports are not cryptographically signed.
- The before/after fingerprints are shown as recorded. This viewer does not independently recreate historical records or prove Google Drive state.
- The audit report contains record identifiers and fingerprints; keep the JSON and HTML reports private.
- Viewing/exporting reports does not apply decisions or sync anything.

## Test on a disposable staging profile
1. Deploy v3.61.0 and confirm About shows `3.61.0`.
2. Open Sync → **View saved audit report (JSON)** and select a known v3.60.0 audit report.
3. Confirm the summary counts, decision rows, hashes, and recovery-point reference context are displayed correctly (the viewer shows the summary and decisions; the recovery-point reference remains in the source JSON).
4. Export the viewer as HTML and open the file locally. Confirm the table is readable.
5. Try an unrelated JSON file; verify it is rejected without changing vault data.
6. Try a report with a malformed hash or inconsistent summary count; verify it is rejected.
7. Confirm local vault, pending journal count, Google Drive vault, shared baseline, and media remain unchanged by viewing/exporting.
8. Repeat a normal upload/retrieve and conflict-review test to ensure the new viewer has not affected existing sync controls.
