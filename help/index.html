FinMate Help & User Guide

A practical guide to setup, records, budgets, goals and synchronization

Getting started: Create a master password, unlock your vault, enter financial records, and make an encrypted backup before moving to another browser or device.

1. First-time setup

  1. Open the official FinMate URL over HTTPS.
  2. On first use in a browser, create a strong master password and store it safely.
  3. Unlock the vault with the master password. PIN or biometric unlock can be enabled later in Settings on supported devices.
  4. Use Settings to choose currency and theme.

2. Add and organize records

  • Wealth: add stocks, mutual funds, PPF, bonds, ETFs, cash/bank balances, and liabilities.
  • Gold: record jewellery metal weight and stone weight separately. Gold weight totals use metal weight. Check the suggested gold rate/current value and edit them if your trusted reference differs.
  • Real Estate: add properties, documents and photos. Link related transactions using the property link tag and assign related liabilities to the property.
  • Transactions: add income/expenses, categories and tags. For an expense, choose whether it should count toward expense totals. Set an overall monthly budget and optional category budgets.
  • Goals: set a target and date, then link the investment assets intended for that goal. Progress and monthly/yearly contribution estimates use recorded asset values and a simple no-growth calculation.

3. Import files

Use CSV/XLS/XLSX files where supported. Review column mapping and the preview before committing an import. Keep the original statement in a secure location. Imported current-price fields represent the source data at import time unless refreshed.

4. Upload or capture documents/photos

In Gold or Real Estate, click the single Add photo/document button. Choose OK to open the camera where supported, or Cancel to select an existing file. Camera behaviour depends on the browser, operating system and device permissions. Documents and images are stored in the local encrypted vault.

5. Google Drive connection

  1. Open Sync and choose Connect Google Drive.
  2. Sign in to your own Google account and approve the requested permissions.
  3. Use Sync Now / Upload to save the encrypted vault, or Retrieve from Drive to restore it on another device.
  4. Before retrieving, confirm you are restoring the intended backup; a restore can replace the current device's data.

Each person should connect their own Google account. Do not share OAuth secrets or your Google password. If OAuth fails, confirm the app origin and callback URI in Google Cloud and the APP_ORIGIN setting in the Cloudflare OAuth Worker.

6. Moving to a new URL, browser or device

Browser storage is origin-specific. Your old vault does not automatically appear on a new domain or in a different browser profile. Before switching, create an encrypted backup and test Drive synchronization/restore. Never clear site data until you have verified a recoverable backup.

7. Troubleshooting

  • App does not update: close and reopen it; if needed, fully close the installed PWA and revisit the HTTPS site after a new release.
  • Drive redirects to an old site: verify the OAuth Worker APP_ORIGIN and the app's configured OAuth Worker URL.
  • Biometrics unavailable: use HTTPS, a supported browser/device, and ensure a screen lock/biometric is configured. Master password remains the recovery option.
  • Photo/camera doesn't open: use HTTPS, allow camera access, and try the file-upload choice if the browser does not support capture.
  • Missing data: confirm the same URL and browser profile are in use. Do not clear storage. Restore only from a backup you trust.

8. Security practices

  • Use a strong, unique master password.
  • Keep encrypted backups in a safe place and periodically test recovery.
  • Do not enter account passwords, PINs or OTPs into FinMate notes.
  • Review the privacy policy before enabling external integrations.

9. Contact and feedback

Use the Contact link above to report bugs, suggest improvements, or ask for help. Do not include passwords, API keys, OAuth secrets, or unencrypted financial data in support messages. The developer must configure a valid email address before public release.
