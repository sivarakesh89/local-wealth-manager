# FinMate v3.47 Drive sync test guide

## Before starting
1. Keep the v3.46.3 deployment and all recovery files unchanged as rollback sources.
2. Deploy v3.47 to a staging GitHub Pages branch/path or use a separate test origin if possible. Do not immediately replace the working production deployment.
3. Confirm your current working profile can open several gold photos and invoices.
4. Use the Google account you intend to use for FinMate Drive. The OAuth origin must be authorized in Google Cloud for the exact deployment origin.

## First backup test
1. Open v3.47 on the device/profile containing the recovered core and media.
2. Unlock FinMate and open Settings → Google Drive.
3. Run Google diagnostics first. If no connection exists, configure the existing OAuth settings and connect.
4. Click **Upload core + media** (or **Backup Now**).
5. Wait for the final success message. A failure during media upload means the backup is incomplete; do not assume the core-only file is sufficient.
6. In Google Drive, verify that `FinMate-vault.json` exists in `FinMate/` and encrypted attachment files exist in `FinMate/media/`. Do not edit these files manually.

## Restore test (required before production reliance)
1. Open v3.47 in a separate Chrome profile or a second device with no important FinMate data.
2. Connect the same Google account and use **Retrieve core + media**.
3. Unlock using the same master password as the source vault. The encrypted media is verified using the vault key.
4. Check transaction totals, several gold-jewellery entries, their thumbnails, enlarged photos and invoices.
5. Confirm that the number of restored attachments matches the source. Keep the source device and original recovery files unchanged until this passes.

## Safety notes
- `Backup Now` is an upload operation, not a merge. It can replace the remote core vault with the current local core vault after uploading media. Do not back up from a stale device.
- `Retrieve core + media` replaces the current local core vault after confirmation; only use it on a fresh/test profile or after making a verified backup.
- Current implementation restores referenced media records but does not implement conflict resolution, tombstones, or record-level incremental sync yet.
- If Google Drive API returns 403/404, check that Drive API is enabled and the configured OAuth client has the correct origins/scopes. Do not paste tokens, client secrets, or your master password into chat.
