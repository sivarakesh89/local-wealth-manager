# FinMate v3.43.0 changelog

- Replaced Dashboard Quick actions for Bank and Recurring with Expense, Income, Upload to Drive, and Retrieve from Drive.
- Dimmed transaction amounts for expenses marked “not counted as expense” and added a small explanatory label.
- Added optional jewellery tags, tag-specific collapsible groups under both Your jewellery and Other jewellery, with untagged items first.
- Added weight/value breakdown by tag in Gold Analytics.
- Removed a redundant vault encryption/persist cycle before Drive upload to reduce preparation delay. Added visible upload/download/decrypt progress and displays encrypted payload size while uploading.
- Added manual encrypted FinMate-vault.json export with a Save As picker where supported, plus local encrypted vault restore.
- Added Target allocation planner by Sector and nested sector-wise rebalancing ideas under Existing individual asset targets.

## Data safety

The IndexedDB database name (`LWMVault`) and encrypted vault format are unchanged. The local file restore feature requires a compatible encrypted FinMate vault; when restoring a file from another device, use the master password associated with that file. Keep exported vault files private.

## Storage and sync note

Drive transfer time still depends on encrypted vault size and network speed. Jewellery photos, invoices, and property documents embedded in the vault can contribute significantly to size. A future architectural improvement would store large media as separate encrypted Drive attachments and keep only references in the main vault; this requires a migration and backward-compatible attachment recovery strategy, so it is not silently introduced in this release.
