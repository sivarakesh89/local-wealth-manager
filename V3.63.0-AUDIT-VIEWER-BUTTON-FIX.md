# FinMate v3.63.0 — Audit Viewer Button Fix

## What changed
- **View saved audit report (JSON)** now uses the browser's file-picker API when available, with a fallback to the normal input click.
- **Export viewer as HTML** is actionable even when no audit report is loaded. It opens the JSON picker, validates the selected report, and automatically exports the HTML after a valid report loads.
- The in-viewer **Export viewer as HTML** and verification-manifest controls remain available as before.
- No changes to the audit JSON format, fingerprint calculation, validation rules, vault, pending-change journal, Google Drive, shared baseline, or encrypted media stores.

## Test checklist
1. Deploy the ZIP contents to the existing GitHub Pages repository and confirm About → Version is `3.63.0`.
2. In Sync → Google Drive, click **View saved audit report (JSON)**. Confirm the file picker opens. Select a valid v3.60.0 audit JSON and confirm the viewer appears.
3. Click **Export viewer as HTML** in the Google Drive action row. Confirm an HTML file downloads and includes the same SHA-256 fingerprint shown in the viewer.
4. Reload the page and click **Export viewer as HTML** before opening a report. Confirm the JSON picker opens; select a valid audit JSON and confirm the HTML export starts after validation.
5. Cancel the picker on either button. Confirm the app remains responsive and no data changes.
6. Select an invalid JSON, invalid hash, and inconsistent-count report. Confirm each is rejected with an explanatory message and no HTML export occurs.
7. Confirm vault contents, pending-change count, Google Drive state, shared baseline, and media remain unchanged.

## Scope and limitations
This release addresses the button/picker workflow only. It does not independently verify Google Drive state or authenticate/sign audit reports. Static checks are not a substitute for testing in the deployed browser.
