# FinMate v3.54.0 — Shared Baseline Foundation

## What it adds
- Keeps the existing secure Compare with Drive authorization flow.
- After a successful comparison, can publish a separate encrypted shared comparison baseline to the existing FinMate Drive folder.
- Publication is offered only when there are zero pending local journal entries and no local-only, Drive-only, or same-ID-different records.
- The shared baseline stores SHA-256 fingerprints and record counts, not raw record contents.
- The file is read back and decrypted for verification after upload/update.
- Does not merge, overwrite, or delete financial records.

## Staging test
1. Keep v3.53.0 and all recovery backups unchanged. Use a staging browser profile and harmless records.
2. Deploy v3.54.0 and confirm About shows 3.54.0.
3. Run Compare with Drive and complete secure authorization if requested.
4. With matching vaults and zero pending changes, save the local baseline and approve publishing the shared baseline.
5. Verify a separate `FinMate-shared-baseline.enc.json` file appears in the FinMate Drive folder; the normal vault file should not be modified by baseline publication.
6. Run comparison again and verify shared baseline can be updated and read-back verified.
7. Create a harmless local-only change or leave pending journal entries, compare, and confirm shared baseline publication is refused.
8. Confirm no records/media changed, and Retrieve remains blocked while local changes are pending.

## Safety boundaries
The shared baseline is encrypted using the current FinMate vault key and should only be used with the same vault credentials/key. It is metadata, not a merge engine, and does not yet automatically compare changes against a baseline on another device. A matching baseline file does not prove the latest vault is correct. Do not use this release to merge or overwrite records.

Source-level checks do not replace live Google Drive/OAuth staging tests.
