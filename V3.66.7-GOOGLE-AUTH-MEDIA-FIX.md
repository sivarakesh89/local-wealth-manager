# FinMate v3.66.7 — Google Authorization & Media Storage Fix

## UI changes
- Adds a dedicated **Authorize Google** button before Upload and Retrieve. It runs the secure Google OAuth flow without automatically uploading or retrieving.
- Upload and Retrieve retain their automatic authorization fallback if the user skips the authorization button.
- Moves sync status and secondary tools into a collapsible **Sync status & other tools** dropdown below the three primary actions.

## Media changes
- Newly saved jewellery media is encrypted and stored in the separate IndexedDB media store immediately; the main vault keeps only a media reference and metadata.
- Before upload, legacy inline data-URL attachments in gold/jewellery and real-estate records are converted to encrypted media-store entries, then the core vault is persisted.
- This makes the media count reflect those attachments and prevents images/invoices from unnecessarily inflating the core-vault JSON. Existing media records are retained.
- A recovery point is created before legacy inline-media normalization during upload.

## Expected behavior for the reported case
The user reported 44 existing media items plus 4 attachments across two new gold entries (one photo and one invoice each). After v3.66.7 externalizes the four inline attachments, upload should process **48/48** referenced attachments, assuming all four files were successfully saved and their encrypted records exist. This expected count is based on the described data, not a live Drive test.

## Safety / validation
- No browser site data or IndexedDB store is cleared.
- No media records are intentionally deleted.
- Upload still verifies the encrypted core vault by reading it back and decrypting it.
- Static checks: JavaScript syntax, manifest JSON, service-worker syntax, ZIP integrity, and targeted code assertions.
- Not tested against the user's live Google Drive account or on a physical Android device.
