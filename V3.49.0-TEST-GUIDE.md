# FinMate v3.49.0 manual test guide

Use a staging deployment and keep the working v3.48.0 deployment unchanged.

1. Unlock the existing vault and verify transaction, asset, jewellery, property, and invoice records.
2. Open Google Drive settings and confirm the pending-local-change count appears.
3. Add a test transaction, save it, and verify pending local changes becomes non-zero.
4. Edit that transaction and save; verify the app continues to show pending changes.
5. Delete the test transaction; verify a tombstone is recorded internally and the pending count remains non-zero. Do not use important records for this test.
6. Attempt Retrieve from Drive while pending changes exist. It must be blocked before replacing local data.
7. Upload core + media. It must complete only after remote core read-back verification; pending local changes should return to zero.
8. Retrieve on a second staging browser profile with no local changes. Confirm the vault and media are intact.
9. On the second profile, make a local edit and attempt retrieval. Confirm retrieval is blocked rather than silently replacing that edit.
10. Reload the app and verify the pending-change count persists across reloads. Lock and unlock and verify it remains readable.
11. Verify the Google OAuth flow, Run Google diagnostics, local recovery points, local encrypted export/import, and jewellery thumbnails still work.

## Expected limitation
The journal is currently device-local. This release does not yet merge individual records across devices or detect two devices editing the same record from a common ancestor. Do not use this as a substitute for the verified whole-vault upload/retrieve workflow.
