# FinMate v2.9.0

## 1. PDF transaction recovery
- PDF imports now keep a recoverable source record even when the first transaction reconstruction is incomplete.
- **Recover PDF imports** now handles current and legacy PDF import records and can rebuild transactions from saved extracted PDF text.
- Recovery always saves and refreshes the Transactions view, and reports how many saved PDF rows were scanned and how many transactions were added.
- Date parsing now explicitly handles common `DD/MM/YYYY`, `DD-MM-YYYY`, and `YYYY-MM-DD` formats.

## 2. Google Drive retrieval on another browser/device
- Retrieve from Drive no longer depends solely on the folder ID stored by another browser.
- If the local folder ID is missing or stale, FinMate rediscovers the app-created **FinMate** folder and vault file.
- If the vault file is not found inside that folder, retrieval also checks the Drive root for the configured vault filename.
- The existing encrypted-vault and secure OAuth architecture is unchanged.

## 3. Investment type detection and numeric fidelity
- The importer now recognizes an **Investment** column as a valid Name/Investment field.
- Type is inferred from the investment name, including Stock, Mutual Fund, Bond, ETF, Gold, Silver, Crypto, FD, PPF, EPF, NPS, Real Estate and Vehicle patterns.
- Generic `Imported Investment` records from earlier releases are upgraded to an inferred type when possible.
- Spreadsheet imports use displayed cell values so the original uploaded numeric representation is retained in the source columns instead of being silently rounded by the importer.
- FinMate monetary display now allows decimal values rather than rounding every displayed amount to a whole currency unit.

## 4. Mobile navigation
- The mobile left drawer now has an explicit scrollable navigation area with a visible scrollbar.
- The drawer itself remains fixed while the menu list scrolls independently.
