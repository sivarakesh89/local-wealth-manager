# FinMate v3.56.0 — Three-way Conflict Review

## Purpose
Adds a read-only **Three-way conflict review** in Settings → Google Drive. It compares:

1. The encrypted shared baseline (`FinMate-shared-baseline.enc.json`)
2. The currently unlocked local profile
3. The current encrypted Drive vault

The baseline is checked for the expected schema, the current Drive vault is downloaded and decrypted, and the baseline's referenced Drive vault file ID must match the current vault file ID. A mismatch stops the review rather than comparing an unexpected file.

## Classifications

- `unchanged-on-both`: both versions still match the baseline.
- `local-only-change` / `drive-only-change`: one side changed while the other still matches the baseline.
- `conflict-both-changed`: both sides changed the same record differently.
- `changed-to-same-content`: both sides changed a record but now contain the same content.
- `local-only-addition` / `drive-only-addition`: a record was added on one side only.
- `concurrent-addition-same` / `concurrent-addition-conflict`: both sides have a record ID absent from the baseline, with matching/different content.
- `local-deletion-candidate` / `drive-deletion-candidate`: a baseline record is missing from one side while the other still matches baseline.
- `local-deletion-vs-drive-edit` / `drive-deletion-vs-local-edit`: one side is missing a baseline record and the other edited it.
- `deleted-on-both`: a baseline record is absent from both copies.

## Safety

- Read-only: no local records, Drive vault, shared baseline, or media are modified.
- Does not merge, delete, upload, retrieve, or apply any decisions.
- Does not create a recovery point because it does not replace data.
- Uses the current unlocked encryption key to decrypt the Drive vault and baseline.
- Exported JSON contains record IDs and labels; keep it private.
- Deletions remain candidates, not proof of user intent.
- Requires a compatible shared baseline and the same current Drive vault file ID referenced by that baseline.

## Staging test checklist

1. Keep the tested v3.55.0 deployment and backups unchanged; deploy v3.56.0 to staging.
2. Confirm About shows `3.56.0` and Settings → Google Drive includes **Three-way conflict review**.
3. With no changes after baseline publication, run the review; expect records to classify as unchanged on both (assuming the baseline and current Drive vault still match).
4. On a staging copy only, create a local-only record and verify `local-only-addition`.
5. On a separate staging copy only, create a Drive-only record and verify `drive-only-addition`.
6. Edit the same record on only one side and verify `local-only-change` or `drive-only-change`.
7. Edit the same record differently on both sides and verify `conflict-both-changed`.
8. Test delete-vs-unchanged and delete-vs-edit scenarios using disposable staging records only.
9. Export and inspect `FinMate-Three-Way-Conflict-Review.json`.
10. Confirm local records, Drive vault, shared baseline, media and pending-change count are unchanged by the review.
11. Confirm secure authorization resumes the review if sign-in is required.
12. Confirm an invalid/missing baseline or a mismatched Drive vault file ID stops safely without changing data.

Source syntax and ZIP checks are not a substitute for live Google Drive testing. Do not use production records for destructive test scenarios.
