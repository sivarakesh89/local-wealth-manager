# FinMate v3.29.0

## User-requested changes

1. Transactions: removed the Amount min/max filter. Amount sorting remains available.
2. Jewellery: photo upload now has a separate camera capture option on supported mobile/tablet browsers.
3. Real Estate: Deed, Patta, Chitta and Other document fields now each support Upload and Camera; property photo also supports Upload and Camera.
4. Jewellery model redesigned around Metal Weight, Stone Weight and auto-calculated Gross Weight. Gold totals use Metal Weight. Added VA, GST, bill upload, and purchase-date historical gold-rate calculation where the configured/current price source provides historical data.
5. Expenses: added a Yes/No radio choice for “Count this as expense?”, defaulting to Yes. No-count entries remain in Transactions but are excluded from expense totals and expense analytics.
6. Axio import: Category names are preserved/matched case-insensitively, Place is imported as Description, Tags are imported, and Axio’s Expense Yes/No flag is respected for expense counting.
7. Wealth: All Assets are grouped into collapsible asset-category dropdowns; categories are shown only when assets exist.
8. Add Expense is available only from Transactions.
9. Custom expense category can be created directly from the Category selector; Settings no longer contains Expense Category Management.
10. Added `PRODUCTION-DEPLOYMENT-GUIDE.md` covering a maintainable public-release workflow with private source, versioned builds, HTTPS hosting, OAuth/Worker separation, backups, migrations and rollback.

## Compatibility / safety

- Existing encrypted IndexedDB vault data is migrated in place.
- Existing jewellery records with the old `weight` field are treated as Metal Weight.
- Existing transactions without `countAsExpense` default to Yes when their type is Expense.
- No master passwords, PINs, OAuth secrets or API keys are requested or embedded.
