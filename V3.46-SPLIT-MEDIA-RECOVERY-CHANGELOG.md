# FinMate v3.46.0 — Split-Media Recovery Build

This is a local recovery-testing build based on the v3.45 recovery build. It adds a split-media import path for very large gold-jewellery recovery vaults.

## New recovery workflow

- Includes `SPLIT-GOLD-MEDIA-RECOVERY.js`, a local Node.js helper that reads a compatible encrypted FinMate v3 vault, decrypts it locally, and produces a compact encrypted core vault plus encrypted media shards.
- Each photo/invoice is encrypted separately with AES-GCM using the recovered vault's data key. Shard files contain encrypted media payloads, not plaintext photo or invoice data.
- The helper replaces embedded gold-jewellery media data URLs with stable media references in both profile and top-level compatibility records.
- FinMate creates a separate IndexedDB `media` object store for encrypted attachment records.
- The app can import multiple media shards sequentially, validating each attachment's authentication and checking that its reference exists in the core vault.
- Gold-jewellery details show attachment buttons for referenced media. Photo/invoice bytes are decrypted only when the user opens that attachment, rather than being loaded into the main vault state at unlock.
- Existing inline-media records remain supported.
- Media import is local-only and does not trigger Google Drive sync.

## Safety notes

- The helper must still decrypt the original large file once. Run it on a laptop/desktop with plenty of free RAM. If Node.js runs out of memory, stop rather than modifying the source file.
- The helper never modifies the source recovery file and writes output to a new folder.
- Keep the original encrypted recovery file and all source backups until the core vault and all attachments have been verified.
- Do not sync to Google Drive until verification is complete.
- This is a recovery build, not a claim that the user's actual 155 MB file has been tested here. Test using the supplied manifest and an isolated Chrome profile.
