# FinMate v3.66.1 — Targeted regression test

## Purpose
Prevent automatic recurring-transaction generation from asynchronously persisting during/after an upload and repopulating the local change journal after it was acknowledged.

## Safe test procedure
1. Keep the v3.66.0 ZIP and a current encrypted vault backup. Do not clear browser storage or delete journal data.
2. Deploy the ZIP contents at the same GitHub Pages location, replacing app files only.
3. Reopen FinMate and confirm About → Version is `3.66.1`; unlock normally.
4. Check Google Drive → Pending local changes. If existing entries are present, upload core + media and wait for the success message confirming read-back verification.
5. Confirm pending local changes is `0`. Reload the page/PWA, unlock, and wait for the dashboard to finish rendering.
6. Confirm the pending count remains `0` if no financial records were changed and no new recurring transactions became due.
7. If a recurring transaction legitimately becomes due, confirm it is present exactly once and that the pending journal reflects the newly created record until uploaded. Upload again and verify the count stays at `0` after reload.
8. Test Retrieve from Drive only when pending is `0`; confirm the existing confirmation prompt and recovery point behavior remain intact.

## Expected behavior
The recurring generator is awaited during unlock. A background persist should no longer race with a completed Drive upload and re-create journal entries after journal acknowledgement. This patch does not erase pre-existing entries or claim that publishing a shared baseline performs synchronization.
