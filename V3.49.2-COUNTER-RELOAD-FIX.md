# FinMate v3.49.2 — Pending Counter Reload Fix

Fixes pending-local-change counter initialization after PIN or biometric unlock. Those unlock paths restored the vault but did not reload the encrypted change journal count, leaving the display at “Checking…”.

## Test safely
1. Keep v3.49.1 and existing backups unchanged. Deploy this complete ZIP to staging.
2. Unlock using the same method you normally use (master password, PIN, or biometric).
3. Open the Google Drive section and confirm the counter resolves to a number.
4. Add a test transaction; verify the count increases.
5. Reload the page, unlock again using the same method, and confirm the counter resolves to a number again.
6. If you have pending changes, do not retrieve from Drive. Upload only after confirming your test data is safe.

This fix does not change journal contents or clear pending changes. It only initializes the displayed count after alternate unlock flows. Live testing against the user's browser and Drive account is still required.
