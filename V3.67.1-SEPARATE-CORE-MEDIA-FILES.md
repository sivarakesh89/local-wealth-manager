# FinMate v3.67.1 — Separate Core and Media Files

## Changes
- Save FinMate vault locally writes `FinMate-core-vault.json` and a separate `media/` folder containing one encrypted JSON file per referenced attachment.
- On browsers supporting the File System Access API, the user selects a destination folder and FinMate creates the core file and media folder there. On browsers without directory access, the core and each media attachment are downloaded as separate JSON files; the browser may require permission for multiple downloads.
- Retrieve from local saved vault asks for the core vault JSON first, then asks for all media attachment JSON files from the media folder in one multi-file selection.
- The restore verifies the master-password-wrapped core, checks each referenced attachment's encrypted payload, confirms no referenced attachment is missing, and saves a local recovery point before applying the restore.
- Updated Help, Privacy Policy, Terms of Service, README and service-worker cache version.

## Safety notes
- This is a local-only export/import flow; it does not upload to Google Drive.
- Keep the core file and media files private and unchanged. Restore using the same master password.
- A restore replaces the current local vault after validation. Do not clear browser storage during testing.
