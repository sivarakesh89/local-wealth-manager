# FinMate v3.66.8 — Media Lifecycle & Pending Count

## UI changes
- Removed the Backup Now button from Sync status & other tools.
- Moved Save FinMate vault JSON locally, Retrieve from local JSON file, and Import media directly below the three primary Google Drive actions.
- Renamed Import recovery media shards to Import media. The same multi-file shard importer remains in use.

## Drive media lifecycle
- Upload still externalizes legacy inline attachments and uploads all media referenced by current gold/property records to the existing `media` folder.
- After the encrypted core vault has been uploaded and read back/decrypted successfully, FinMate now lists the Drive media folder and deletes `attachment-*.json` files whose media references are no longer referenced by the current vault.
- Media deletion is intentionally delayed until after core read-back verification. If deletion fails, FinMate reports an incomplete cleanup and does not acknowledge the local change journal as fully synced.
- Local IndexedDB media records are not deleted by this cleanup, preserving local recovery-point compatibility.

## Pending changes
- The existing journal diffs tracked collections including transactions (income and expense records), gold jewellery, and real estate by stable record ID.
- Journal entries are coalesced by collection + record ID, so creating/editing/deleting one record contributes one effective pending item rather than one per field or repeated edit. Creating then deleting an unsynced record cancels out. Deleting an existing record creates a deletion tombstone.
- A media attachment change is represented by the owning gold/property record change; attachments are not counted as separate financial entries.

## Safety and validation
- No browser storage, vault, journal, or local media database is cleared.
- Static validation performed: JavaScript syntax, service-worker syntax, manifest JSON, ZIP integrity, and assertions for the requested button placement, renamed label, removed Backup Now action, and media cleanup hook.
- No live Google Drive or real-browser end-to-end test was performed in this environment. Verify the new release using the supplied checklist before relying on Drive-side deletion behavior. Keep an encrypted backup and the v3.66.7 ZIP.
