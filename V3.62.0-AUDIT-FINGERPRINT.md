# FinMate v3.62.0 — Audit Fingerprint & Verification Manifest

## What changed
- Calculates a canonical JSON SHA-256 fingerprint when a supported conflict-apply audit JSON is opened.
- Displays the fingerprint in the Sync-page audit viewer and includes it in the HTML export.
- Adds an optional `FinMate-Audit-Verification-Manifest.json` export containing the fingerprint, report metadata, validation result, and summary counts.
- Remains read-only: it does not store the report in the vault or modify vault records, pending journal, Google Drive, shared baseline, or media.

## Security limitation
The fingerprint is useful for comparing copies and detecting accidental or unsynchronized content changes. It is not a digital signature. A person who can alter both the report and its manifest can recalculate the fingerprint; it does not establish who created the report, prove Drive state, or independently prove the original record contents.

## Staging test plan
1. Deploy to a disposable profile and confirm About shows `3.62.0`.
2. Open a known valid v3.60.0 audit JSON and confirm it is accepted.
3. Record the displayed canonical SHA-256 fingerprint; reopen the same file and confirm the fingerprint is identical.
4. Export the HTML and confirm the same fingerprint appears in it.
5. Export the verification manifest and confirm the report fingerprint, report format, and summary counts match the viewer.
6. Change a decision label or hash in a copy of the JSON (keeping structure/counts valid); confirm it opens only if structural checks pass and the fingerprint changes. This demonstrates content comparison, not authenticity.
7. Repeat the unrelated JSON, malformed hash, and inconsistent count rejection tests.
8. Confirm vault, pending-change count, Drive, baseline, and media remain unchanged.

Do not clear browser site data for this update. Keep previous release ZIPs and backups unchanged until staging tests pass.
