# FinMate v3.53.0 — Secure Compare Authorization + Local Baseline Foundation

## Changes
- Fixed the `Compare with Drive failed: Secure Google authorization is required.` path. When the secure refresh token is missing/expired, Compare now starts the configured secure OAuth Worker flow and resumes comparison after the OAuth callback and vault unlock.
- Added an optional encrypted, device-local comparison baseline after a successful comparison. It captures record hashes/status metadata and the Drive file ID/modified time in IndexedDB `syncmeta`.
- The baseline is local to this browser, is not uploaded to Google Drive, and does not apply conflict decisions or merge records.
- Existing Retrieve protection for pending local journal entries is unchanged.

## Staging tests
1. Keep v3.52.0 and all recovery backups unchanged.
2. Deploy v3.53.0 to a staging copy/separate browser profile; verify About shows 3.53.0.
3. In staging only, test Compare with Drive with no usable cached access token. Confirm secure Google sign-in starts instead of showing the old authorization error.
4. Complete sign-in and unlock FinMate. Confirm comparison resumes and displays the record counts.
5. Choose to save the device-local baseline. Confirm success; then reload/unlock and confirm the vault, media, and pending-change count are unchanged.
6. Confirm no new baseline file appears in Google Drive and no local/Drive records were changed by compare or baseline save.
7. Confirm Retrieve remains blocked while local journal entries are pending.
8. Repeat compare after authorization is available and confirm it works without a new sign-in unless the backend requires reauthorization.

## Safety / limitations
- Do not test by deleting or replacing the live vault. Use harmless staging records.
- Baseline is currently device-local, not shared across devices; it is a foundation for future review, not a conflict resolver.
- This build has source-level checks only; live OAuth and Google Drive validation must be done in your staging environment.
