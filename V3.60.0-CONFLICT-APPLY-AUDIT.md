# FinMate v3.60.0 — Conflict Apply Audit Report

## What changed

After a successful local conflict-resolution apply, FinMate offers to export `FinMate-Local-Conflict-Apply-Audit.json`. The report records each worksheet decision, the record ID and label, whether the local record existed before/after, and SHA-256 fingerprints of local state before/after. It also records the recovery-point ID and summary counts. It does not contain full financial record values.

The report is optional and only offered after the local vault save succeeds. `KEEP_LOCAL` is recorded as unchanged; `KEEP_DRIVE` is recorded as the Drive version being applied locally. The report is generated client-side and is not uploaded anywhere.

## Safety boundaries

- Existing v3.59.1 checks remain: explicit decisions, zero pending journal changes, matching baseline/Drive IDs, fresh local and Drive fingerprints, and a local recovery point before mutation.
- The apply operation remains local-only. It does not upload the vault, change the shared baseline, or modify media.
- The audit JSON can expose record identifiers and labels. Store it privately and delete it when no longer needed.
- A recovery point is the rollback mechanism; the audit report itself cannot restore records.

## Staging tests

1. Deploy v3.60.0 and confirm About shows `3.60.0`.
2. Generate a fresh three-way review and export a new XLSX worksheet.
3. On disposable staging records, choose one `KEEP_LOCAL` and one `KEEP_DRIVE`; apply the worksheet.
4. Confirm the success message appears and the optional audit-report prompt follows.
5. Export the JSON report and confirm it includes the recovery-point ID, decisions, before/after SHA-256 values, and counts, without full record contents.
6. Verify the local record selected as `KEEP_DRIVE` matches the reviewed Drive version; the `KEEP_LOCAL` record remains unchanged.
7. Confirm Drive vault, shared baseline, and media remain unchanged by the apply operation. Confirm pending-change count and recovery point are consistent with the local save.
8. Decline audit export and verify the apply still completes successfully.
9. Repeat unresolved-decision and stale-workbook tests; both must still be rejected before mutation.

## Validation performed here

JavaScript syntax, service-worker syntax, manifest JSON parsing, and ZIP integrity are checked during packaging. Live browser, Google Drive, and physical-device end-to-end tests must be completed in staging; they are not claimed as performed by this build step.
