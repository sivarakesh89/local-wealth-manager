# FinMate v3.65.0 — Audit Verification Receipt

## Purpose
Adds a read-only export of the latest saved-manifest verification result. The receipt records the report fingerprint and summary, selected manifest filename, check timestamp, MATCH/MISMATCH result, and each individual check.

## Test checklist
1. Keep v3.64.0 ZIP and existing backups unchanged.
2. Deploy the contents of this ZIP to the existing GitHub Pages repository.
3. Confirm About → Version shows `3.65.0`.
4. Open a valid v3.60.0 conflict-apply audit JSON.
5. Click **Export verification receipt** before verifying a manifest. Confirm FinMate explains that a verification result is needed and does not download a receipt.
6. Export a verification manifest, then click **Verify saved manifest** and select the matching manifest. Confirm all seven checks pass.
7. Click **Export verification receipt**. Confirm a JSON file downloads with `result: MATCH`, seven individual passed checks, the same report fingerprint, report summary, manifest filename, and verification time.
8. Verify a manifest with a changed fingerprint and export another receipt. Confirm it records `result: MISMATCH` and identifies the failed check(s).
9. Open the receipt in a text editor and confirm it contains no vault transactions, account details, asset records, or media data.
10. Confirm the vault, pending-change count, Drive, shared baseline, and media remain unchanged.
11. Test malformed/unrelated manifest JSON and cancel the picker; FinMate should remain usable.

## Safety and limitations
- Receipt generation is local and read-only. It does not upload or persist anything to the vault, Drive, shared baseline, or media.
- The receipt is not digitally signed. Anyone can edit JSON and recompute hashes; it records what this session reported but cannot independently prove authenticity.
- No live GitHub Pages/browser or Google Drive test was performed as part of packaging.
