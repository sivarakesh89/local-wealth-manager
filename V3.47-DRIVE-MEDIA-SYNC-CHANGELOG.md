# FinMate v3.47.0 — Drive media sync (first-stage)

## Changes
- Re-enabled manual Google Drive backup and restore in the v3.46.3 recovery baseline.
- Keeps the compact encrypted core vault as `FinMate-vault.json`.
- Stores encrypted attachments independently in `FinMate/media/` as one JSON record per stable attachment reference.
- Verifies each downloaded attachment by decrypting it with the unlocked vault key and checking that the plaintext begins with a data URL before storing it locally.
- Uses Drive resumable upload sessions for media records and processes attachments one at a time.
- Uploads media before publishing the core vault, so a missing local attachment prevents the core backup from being updated.
- Updates service-worker cache name to v3.47.

## Important limitations
- This is a manual backup/restore milestone, not conflict-safe bidirectional merge. `Backup Now` uploads local state; `Retrieve from Drive` replaces local core state after confirmation.
- Do not edit the same vault independently on both devices and then back up from both. Restore the chosen latest backup to the other device first.
- No end-to-end browser test was possible in this environment. Test with the same Google account and a separate Chrome profile before relying on this build.
- OAuth backend and Google Cloud scopes/configuration are not changed by this ZIP. If Drive access fails, use Settings → Google Drive → Run Google diagnostics.
- The media records remain encrypted with the FinMate vault key; filenames contain attachment references, so Drive metadata may reveal reference identifiers even though media contents are encrypted.
