# FinMate v3.30.0

## User-requested changes

1. First-run setup: after creating the Master password, FinMate immediately opens the unlock screen so the user can enter the password without manually refreshing the browser.
2. Biometric unlock: clicking Fingerprint / biometrics now invokes the device WebAuthn biometric prompt directly from the user action instead of showing a second unlock button.
3. Wealth: removed the ticker/symbol explanation panel from the bottom of the Wealth page. Ticker/symbol fields used for market data remain available where required.
4. Real Estate property linking: added an Expense link tag to each property. Related expense transactions can be linked by selecting the property in Add Expense, which also adds the property's tag. Existing transactions can be linked by adding the same tag manually.
5. Real Estate property details now show linked transactions/expenses and a linked-expense total directly inside each property entry.
6. Liabilities: added a Link to property selector. A liability can be assigned to an existing property and will then be shown under that property's Linked liabilities section.
7. Added migration defaults for property link tags and liability property links so existing vaults remain compatible.
8. Expanded `PRODUCTION-DEPLOYMENT-GUIDE.md` with a minute-by-minute distribution workflow, release packaging, GitHub Pages setup, HTTPS checks, Google OAuth/Drive setup for each user, testing, backups and rollback.

## Compatibility / safety

- Existing encrypted IndexedDB vault data is migrated in place.
- No master passwords, PINs, OAuth secrets or API keys are requested or embedded.
- Google Drive remains per-user: each user authorizes their own Google account and FinMate stores only the encrypted vault in that user's Drive.
