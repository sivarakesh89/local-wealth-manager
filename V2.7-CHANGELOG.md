# FinMate v2.7.0

## Imports
- Expanded ticker/symbol detection with mutual-fund name search through MFapi and best-effort Yahoo Finance symbol search.
- Imported holdings now use the resolved ticker even when the source file has no ticker column. Original source headings/rows remain unchanged.
- PDF transaction extraction now groups wrapped statement lines, normalizes Income/Expense types to lowercase, and stores them in the Transactions list.
- Added **Recover PDF imports** to reconstruct transactions from previously stored PDF import rows from older FinMate versions.

## Google Drive
- Canonicalized the GitHub Pages redirect URI so `/index.html` is normalized to `/`, avoiding redirect mismatch caused by opening the page through a different path.
- If GIS reports `popup_closed`, FinMate now offers the full-page compatibility flow automatically.
- Added a recommended **Secure OAuth backend** option for the long-term solution. The supplied Cloudflare Worker uses Google authorization-code flow and keeps the Google client secret off GitHub Pages.
- The worker receives OAuth credentials only; the FinMate vault remains encrypted in the browser before Drive sync.
- Refresh tokens returned by the backend are stored only inside the encrypted FinMate vault after unlock.

## Security
- No Google client secret is stored in the PWA.
- The legacy full-page implicit flow remains available only as a static-hosting compatibility fallback. Google currently recommends authorization-code flow for modern web applications.
