# FinMate v3.49.1 — Pending Local Change Counter Fix

This is a focused UI fix for v3.49.0. The journal was present, but its count was not rendered in the Google Drive status panel.

## Changes
- Displays `Pending local changes` in the Google Drive sync status panel.
- Caches the journal count after it is read, updated, or cleared so the UI can show it.
- Bumps the application and service-worker cache version to v3.49.1.

## Safe test
1. Keep your v3.49.0 deployment and encrypted backups unchanged.
2. Deploy the complete ZIP to a separate GitHub Pages staging branch/site if available.
3. Unlock FinMate and open the Sync page / Google Drive section.
4. Confirm `Pending local changes` is visible. It may briefly show `Checking…` before the count loads.
5. Add and save a test transaction. Reopen the Sync page and confirm the counter increases.
6. Upload core + media and confirm the counter returns to zero only after the verified upload completes.
7. Do not use Retrieve as a test while the counter is non-zero; it should block to protect local changes.

This release does not introduce cross-device record-level merging. Keep v3.49.0 and your existing backups until staging tests pass.
